# Portable evidence graph round trip

`.cauchyreading` format version 2 can carry an optional `evidence.json` beside the PDF and `session.json`. The evidence file contains the completed reference index, its `builtWith` and `builtAt` provenance, exact source offsets, and the observed later-mention graph. Export generates or reuses the deterministic local graph only when the current reference index completed without failed pages. A missing or damaged optional local cache does not prevent exporting ordinary reading progress.

Import treats the package as untrusted. It requires the evidence schema, reference-index schema, graph schema, and three document fingerprints to agree with the packaged PDF's freshly computed SHA-256. Reference pages and offsets must be in range; every source excerpt must equal the PDF text at its recorded offsets; every definition and mention must resolve to the exact printed page region; graph nodes must match reference-index nodes; serialized mention context must reproduce from the PDF; paths must be leaf filenames rather than links or traversal; and evidence size and counts are bounded. Invalid declared evidence rejects the package rather than being silently installed.

The automated acceptance test creates a searchable one-page PDF containing a theorem declaration and a later citation, seeds a grounded reference index, exports a reading session, then removes both local caches. Import restores the reference index, on-device provenance, and the single anchored edge without a model call. Appending bytes to the packaged PDF makes evidence validation fail, demonstrating byte-level binding. A separate compatibility path rewrites a package manifest to version 1 with no evidence field and confirms it still opens with its PDF, reading progress, and highlights.

The reader now loads a graph whose node set matches the current reference cache and uses it before falling back to an on-demand PDF scan. A missing or stale graph rebuilds locally in one PDF pass; a partially failed reference-index build does not claim a complete graph. This verifies serialization, validation, cache installation, and reader data flow. A fresh interactive-window check of the updated panel and manual save/open dialogs remains separate.
