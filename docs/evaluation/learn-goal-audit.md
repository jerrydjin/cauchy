# Learn advancement and design audit

The request is to advance the distinct Learn experience, review Linear and add useful tickets, prevent information overload, remove loose examples/warnings, and deliver a polished native experience. The additional user constraint is to keep system settings unchanged. This audit checks those requirements against the current implementation and retained runtime evidence.

| Requirement | Current implementation and evidence |
| --- | --- |
| Continue Learn development with useful features | Contextual step/question clarification preserves per-context drafts, source provenance and assessed-answer boundaries (`LearningClarification`, `LearningViewModel`, `LearningClarificationView`; [verification](learning-clarification.md)). Bounded study sessions offer a preview, exact-target continuation, pause/resume, an explicit stop and truthful records (`LearningStudyRun`, its coordinator and views; [verification](study-sessions.md)). |
| Review and maintain Linear | The Cauchy project was reviewed against current code/evidence. JERRY-61/64 track hierarchy and contextual help, JERRY-62/63 track the new features, and JERRY-75/77/78 capture concrete native inspection findings and their fixes. Each has repository evidence and local checkpoint references; implementation-ready items remain available for user review rather than being silently declared released. |
| Prevent information overload | The course shows one recommended action before collapsed chapters/course administration. Lesson, review, chapter and bounded-session recommendations use compact titles and contextual details. The active chapter leads with its question/editor, while introduction/sources/refresher guidance are disclosed. History now has a concise status line with full provenance in read-only details. Inspected at the native 1000-point minimum, including source-inspector layouts and a 15-session history. See [course/question polish](learn-design-polish.md), [long layout checks](learning-layout.md), [review/chapter checks](learning-next-actions.md) and [history checks](learning-history.md). |
| Keep examples, warnings and metadata in context | Worked examples retain an explicit teaching part/full-lesson location. Repeated goals, help, source qualifications and attempt histories live beside the relevant task in disclosures. Independent-check instructions attach to help reporting beside submission. Source blockers remain actionable with their source-review control; assessment uncertainty remains attached to feedback. Generic trailing coaching and loose chapter/refresher guidance were removed. Current `LearningSessionView`, `LearningStudyMapView`, `LearningStudyRunView` and `LearningClarificationView` match the inspected behavior. |
| Deliver a polished, usable native flow | Native sidebar/toolbar/inspector, semantic content backgrounds and glass controls are retained. Narrow lesson navigation keeps Continue reachable; typing reveals the answer editor without hiding the arriving question. Full requirements/proofs remain readable. Native keyboard checks cover lesson/clarification return, requirement reading, bounded planning/pause/restart/resume/finish, metadata selection changes and Escape focus return. Exact drafts/questions/help/assessments survive navigation/restarts. The history switching check exposed and corrected a stale toolbar shortcut capture. Reports above record the specific screens, actions and snapshots. |
| Preserve the separate reader workstream and saved learning evidence | [Synchronization evidence](workstream-sync.md) pins the adopted integration. Models, view models and services remain unchanged from integration `188d560`; subsequent design work is limited to Learn views and the coordinated focused Learn menu actions. The combined menu baseline passed 344 macOS tests; final history actions passed 74 relevant tests, followed by the native-verified heading-only build. Saved-record comparisons in the reports verify the actual data preservation rather than inferring it from appearance. |
| Keep system settings unchanged and checks honest | The user manually unlocked the Mac when required. No VoiceOver, appearance or display-accessibility settings were changed. Reports explicitly distinguish native authored-fixture interaction/layout checks, recorded live prompt observations, automated policy regressions and unexercised variants. |

The requested advancement and focused-design work is implemented and verified for review. No known acceptance work remains in these deliverables after the recorded native fixes. Native evidence covers the stated interaction/layout scenarios; it does not establish general mathematical/model accuracy, an exhaustive keyboard/VoiceOver audit or alternate display-setting behavior. Those broader claims are not used to establish completion of this request. Local checkpoints are not a push or release.
