# Find saved lessons

Tracked by [JERRY-84](https://linear.app/jerryjin/issue/JERRY-84). **Find a Saved Lesson…** in Learn, ⇧⌘F, and the Learn toolbar open a local search panel for the selected notes. The current lesson stays in place until an explicit Open, Return or double-click. Cancel/Escape restores the prior task. The existing reader Find/⌘F actions are unchanged; the shared command-file change only registers the focused Learn action and its Learn menu item.

Search covers titles, goals, activity/kind/status, current or previously submitted question prompts, learner answers/drafts, feedback/criterion feedback, saved clarification questions/replies and clarification drafts. Chapter refresher drafts and attempts stay attached to their chapter. It deliberately excludes answer keys, hints, future assessment prompts, PDF text and unrelated notes. Matching is case/diacritic insensitive, with every whitespace-separated term required somewhere in the record. Results preserve recent-work order with a deterministic tie break and show a bounded matching excerpt where available. Empty queries return recent records without scanning their content.

The panel identifies the current document and searchable content, updates as text changes and keeps search transient. This follows Apple's guidance to make [search scope clear](https://developer.apple.com/design/human-interface-guidelines/searching) and use [helpful placeholders and immediate results](https://developer.apple.com/design/human-interface-guidelines/search-fields). Full titles remain in accessible/hover text and the existing Lesson details panel after opening a result. No search data is sent to an assistant or external service; no search index or learning persistence schema is added.

## Verification — 20 October 2026

The final **complete macOS suite passes 372 tests, zero failures or skips** (`/tmp/cauchy-search84-verified.xcresult`; `/tmp/cauchy-search84-verified.log`). Seven new regressions cover case/diacritics and multi-field terms, hidden key/hint/future-prompt exclusion, historical answers/feedback/clarification drafts, deterministic same-title attempts, Unicode excerpts, real persistence/restart preservation after search/open, and chapter-refresher work remaining attached to its challenge. `git diff --check` passes.

An initial full run passed 371 tests before the extra chapter regression, but native inspection exposed that SwiftUI's text-field key handler did not receive Down while editing. Return therefore reopened the initially selected result. The final field uses `NSSearchField` and its native delegate movement/return/cancel commands, preserving normal text editing. It disables recent-search storage, focuses once on presentation and uses native clear behavior. The corrected native path, rather than automated policy tests, establishes the keyboard interaction below.

Native checks used `/tmp/CauchyLearnSearch84.app`, a separate Debug bundle, and `/tmp/cauchy-ui-fixture-search84-native` in a 1000-point dark window. The disposable authored fixture contains 15 sessions: a same-title ordinary/delayed pair, an unsent delayed draft, a long title and an accented title. It contains no real learner notes. Screen-capture failures recovered by selecting the same running process; restart checks below were deliberate persistence tests, not recovery relaunches.
