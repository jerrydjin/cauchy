## Implementation boundaries

Reconciliation searches every page's text, ranks complete pages by topic and exact numbered references, and follows additional page requests. It is bounded retrieval followed by model review of retrieved pages, **not** a semantic reading of every page for every warning. Each saved topic records the total text-search scope, exact pages supplied to the model, assistant/model, timestamp, disposition, original warning index, and exact continuous quotes on their stated pages. Evidence uses one-based PDF page numbers in JSON; the app uses zero-based page indices internally.

Dispositions distinguish source located, explicitly omitted, exercise obligation, prerequisite, extraction problem, and not located. Only a fully resolved source-located warning lowers the open-candidate count. Partial findings remain open. Literal quotes are required for positive findings, explicit omissions, exercises, prerequisites and extraction concerns. No evidence means not located. A failed quote gets a bounded repair request with the precise validator error, not a relaxed validator.

Original warnings, source quotes, proof flags, unit/target IDs, course order, sessions and answers are retained. A complete newly located proof may add one persisted **unchecked** proof target only when all of that topic's source issues are resolved. Existing proof and rubric validation still applies to teaching and assessment. A new proof target creates no attempt or grade. Missing usable proof sources remain explicit, even when the other available targets pass.

Each validated topic saves atomically using the existing learning persistence callback. Cancellation checks after model responses discard late results; resumption skips completed reviews. A changed PDF text signature prevents reuse. A source page that exceeds capacity is never clipped. Reference lookup that cannot fit or finish stays explicitly not located with the requested pages retained in its explanation. The tutor's remote context budget now also accommodates complete reconciled source pages throughout teaching and assessment.

The learner keeps one next lesson action. Source-review totals and grouped classifications are disclosed separately; a topic exposes its concise findings, original warnings, exact evidence and review scope. A focused topic review is available inside those details. The new controls use native SwiftUI disclosure groups and buttons; existing Liquid Glass controls, semantic colors and Reduce Motion behavior remain in place. Source faults block new generation for the affected topic, while existing saved lessons remain inspectable.

## Native visual fallback

The implementation reuses Cauchy's existing `PDFRegionRenderer` and local Vision `OCRService`: accurate recognition, language correction disabled, raw recognized lines retained. OCR is available only as an explicitly labelled inspection aid beside an extraction issue. It cannot replace source text, clear a warning, unlock a lesson, or become a proof quote. Mathematical OCR is not trusted to repair a missing radical or union.

Current primary API references checked for this pass: [Apple text recognition](https://developer.apple.com/documentation/vision/recognizing-text-in-images), [language correction](https://developer.apple.com/documentation/vision/vnrecognizetextrequest/useslanguagecorrection), [PDF page thumbnail](https://developer.apple.com/documentation/pdfkit/pdfpage/thumbnail(of:for:)), and [Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass). Apple documentation was also queried through Context7. No new paid service or model provider was introduced.
